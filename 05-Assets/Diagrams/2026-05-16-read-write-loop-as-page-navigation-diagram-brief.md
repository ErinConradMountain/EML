## Purpose

Create a visual bridge between the Read-Write Model and the Knowledge-Space/Semiotics lane. The diagram should show the read-write process as navigation across a page-terrain, not as a mechanical linear workflow.

## Core Claim

The page becomes a navigable knowledge space when handwritten anchors, AI projections, re-entry marks, revision paths, and drift-control checkpoints are made visible in relation to one another.

## Diagram Structure

Use a single page or spread with six connected zones:

| Zone | Function | Visual Treatment |
| --- | --- | --- |
| 1. Handwritten anchor | Original embodied inscription | Black ink mark or small note cluster |
| 2. Projection field | AI externalises possible structure | Blue frame, outline, or expanded field |
| 3. Re-entry mark | Human reads back into projected form | Black return arrow plus marginal mark |
| 4. Revision path | Learner alters thought through judgement | Green movement path |
| 5. Drift checkpoint | Detect flattening, distortion, or emergence | Small coordinate marker or checkpoint node |
| 6. New inscription | Revised thought returns to handwriting | Black mark with yellow emergence highlight |

## Suggested Layout

```text
[1 Handwritten Anchor] ---> [2 Projection Field]
          ^                         |
          |                         v
[6 New Inscription] <--- [5 Drift Checkpoint] <--- [4 Revision Path] <--- [3 Re-entry Mark]
```

Alternative layout:

```text
Page terrain with coordinates:

Top left: original handwritten anchor
Top right: AI projection field
Centre: re-entry mark
Lower right: revision path
Lower centre: drift checkpoint
Lower left: new handwritten anchor
```

The second layout may better support EML's page-as-navigation principle because it lets the reader see movement across a surface rather than only around a loop.

## Visual Language

- Black ink: human inscription, return, and judgement.
- Blue: structure, projection, outlining, externalised form.
- Yellow: emergence, new insight, unexpected value.
- Green: growth, revision, development, viable continuation.
- Small coordinate marks: stable return points.
- Arrows: movement, not command.
- Marginal notes: human re-entry and contestation.

Keep the diagram restrained. It should feel like a field notebook made more legible, not a corporate process chart.

## Labels

Use short labels:

- Anchor
- Project
- Re-enter
- Revise

Optional side note:

```text
The loop trains the human model through return.
```

## Classroom Interpretation

This diagram can later become a classroom-facing circuit:

1. Learner writes a rough idea.
2. AI or teacher helps project structure.
3. Learner compares output with original thought.
4. Learner marks what changed.
5. Learner revises by hand.
6. Learner explains what shifted.

## Open Design Questions

1. Should the projection field be shown as a screen, a page, or a second layer over the original page?
2. Which visual mark best represents re-entry: arrow, margin note, highlight, or rewritten phrase?
3. How can the diagram show productive drift without making drift look like an error?
4. Should the final inscription return to the same page or begin a new page?
