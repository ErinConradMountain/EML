EML Project Agent Instructions

EML Project Agent Instructions Purpose: support authoring the EML book through weekly notebook synthesis, clear documentation, and consistent visual-language planning. Scope Focus on the EML book plan, field journal, and supporting artifacts. Keep work grounded in existing documents; ask before introducing new frameworks. Assume weekly notebook updates will continue through 2026. Primary Goals Maintain the four-part book structure (Orientation, Grammar, Circuits in Practice, Futures). Convert notebook material into book-ready assets: diagrams, short readings, chapter notes. Preserve the model-in-book-form vision: visual-first, reflective, slow and precise. Cultivate and refine the author's own voice and lexicon over time, grounded in handwritten notes and daily writing. References Follow the project plan in 08-Admin/Plans/EML-Book-Plan-2026.md. Use 05-Assets/Templates/Weekly-Intake-Template.md for weekly notebook synthesis. Working Style Prefer concise summaries and structured outputs (headings, checklists, templates). Capture decisions and next actions explicitly. Use consistent terminology from EML (structural layer, cognitive-temporal layer, agentic layer). Run the full weekly intake template 05-Assets/Templates/Weekly-Intake-Template.md every week so Steps 0-10, asset mapping, style notes, and the bridge checklist stay active. Voice and Lexicon Development Treat handwritten notebooks and daily entries as the primary source for tone and vocabulary. When rewriting or summarising, preserve characteristic phrases and metaphors rather than smoothing them into generic language. Notice and surface recurring expressions into a living lexicon (e.g., terms, definitions, micro-stories) that can be reused and sharpened across weeks. Allow the written voice and preferred terminology to evolve; each week should be an opportunity to extend, refine, or correct prior formulations. Instructions History as a Working Surface Treat 08-Admin/Instructions/EML-Project-Instructions-History.md as an active artefact, not an archive: it is a running log of how the project's instructions, cycles, and definitions evolve. At the start of a new working session or when instructions feel unclear, scan the latest dated entry to align with the current operating rules before acting. When instructions are changed in chat (e.g., refinements to the Learning Journal Cycle, voice guidelines, or workflows), append a new dated entry to the history file summarising what changed and why. Periodically (for example, monthly or when requested), analyse the history entries to surface patterns: recurring concerns, shifts in emphasis, or stable rules that can be promoted into 08-Admin/Instructions/agent.md or the main book plan. Reuse and, when appropriate, merge earlier instruction patterns rather than reinventing them; explicitly note when a new instruction supersedes or updates an older one. Workflow Expectations When given new notes, produce: A 1-page synthesis. 3-5 tags mapped to book parts and EML layers. 1-2 candidate diagrams or circuits. When drafting, always cite which source sections you are using. Keep a running list of gaps and missing evidence by book part. Treat the capture flow as an intake-digestion-redistribution architecture (see 05-Assets/Readings/Learning-as-Inscriptional-Emergence.md), and protect the weekend ingestion layer for listening, reflection, and scaffold thickening before the next cycle (see 05-Assets/Readings/Weekend-Ingestion-Layer.md). Visual Language Guidance Maintain a restrained visual grammar: black ink line drawings, small color accents. Use recurring symbols and reintroduce diagrams with added resolution. Tie each diagram to a short reflective prompt. Output Formats Prefer Markdown files for plans, syntheses, and draft sections. Use stable filenames with dates when capturing new material. Avoid long prose dumps; favor modular sections that can be reused. Communication Ask clarifying questions when intent is ambiguous. Suggest next steps only if they are natural and minimal. Learning Journal Cycle – Chat Instructions When the user invokes the Learning Journal Cycle, follow the six-step process (Steps 1–6) as currently defined in 08-Admin/Plans/EML-Book-Plan-2026.md and documented in 08-Admin/Instructions/EML-Project-Instructions-History.md (version dated 2026-01-18). Treat Steps 1–3 (Polished Notes, Analytical Study, Academic Essay) as the default engine; use Steps 4–6 selectively when explicitly requested or when the user clearly signals a topic is ready to be translated, distilled, or tested. Keep each step as a distinct response, clearly labelled (e.g., "Step 2 – Analytical Study"), and avoid collapsing analysis, extension, and study guide into a single block. In Steps 1 and 2, stay tightly faithful to the handwriting (content, sequence, intent); in Steps 3–6, make extensions explicit and note where you generalise or depart from the original notes. Throughout all steps, preserve and reuse characteristic phrases, metaphors, and terms from the handwriting, and surface emerging vocabulary that feels uniquely the author's, contributing to a living lexicon over time.
